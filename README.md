# Распознавание облачности на спутниковых снимках

Кейс компании «Спутникс» (SK KIDS CHALLENGE, направление «Космические технологии»).

## Задача

Кубсаты «Спутникс» делают много снимков Земли, но значительная часть закрыта
облаками. Нужен алгоритм, который сам определяет, сколько процентов кадра
закрыто облаками, и не пропускает в дальнейшую работу снимки, закрытые более
чем на 75%. По ТЗ после обработки оператор получает сообщение, где указаны
сохранённые и удалённые файлы с процентом облачности.

## Как устроено решение

Алгоритм состоит из четырёх шагов: нормализация → сегментация → подсчёт →
решение.

1. **Нормализация.** Камеры кубсатов не калиброваны: снимки получаются
   синеватыми и малоконтрастными из-за атмосферного рассеяния. Сеть, trained
   на «правильных» космических снимках, принимает такую дымку за облака.
   Поэтому перед распознаванием кадр приводится к виду обучающей выборки:
   если в кадре есть тёмные пиксели, контраст растягивается по перцентилям
   2–98%.
2. **Сегментация.** Свёрточная сеть U-Net (архитектура 2015 года, стандарт
   для медицинских и спутниковых снимков) размечает каждый пиксель кадра:
   облако или нет. Сеть устроена как «воронка»: сначала сжимает изображение,
   накапливая признаки на разных масштабах, затем разворачивает карту признаков
   обратно до исходного разрешения, соединяя детали с ранних слоёв.
   В качестве энкодера используется ResNet18, предобученный на ImageNet.
3. **Подсчёт.** Процент облачности = облачные пиксели / все пиксели × 100.
4. **Решение.** Если процент строго больше 75 — снимок отбраковывается
   (по умолчанию перемещается в папку rejected/, ключ --hard-delete включает
   безвозвратное удаление, как в ТЗ). Остальные копируются в accepted/.

Оба шага работают и на больших кадрах: снимок 3280×2464 режется на куски
512×512 с перекрытием, предсказания усредняются.

## Обучающие данные

В открытом наборе «Спутникс» (disk.sputnix.ru) около 4200 снимков с камер
кубсатов, но разметки (масок облаков) там нет. Поэтому модель обучалась на
открытом датасете 38-Cloud: 8400 фрагментов снимков Sentinel-2 размером
384×384 с масками облаков, а к снимкам «Спутникс» применяется уже готовая
модель. Это стандартный приём (transfer learning). Дополнительно написан
генератор синтетических снимков с точной разметкой — он используется для
проверки пайплайна и демонстрации.

## Результаты

Модель обучена на RTX 4060 Ti примерно за 34 минуты (16 эпох + дообучение).

| Метрика | Значение |
|---|---|
| IoU (пересечение/объединение маски) | 0.904 |
| Dice (F1 пикселей) | 0.904 |
| Precision | 0.945 |
| Recall | 0.920 |
| Ошибка процента облачности (MAE) | 2.26 п.п. |
| Точность решения «браковать/сохранить» | 96.8% |

Проверка на реальных снимках «Спутникс»: ясная река — 2.2%, облачный океан —
72.4%, по-настоящему облачный кадр — 77.4% и отбракован.

## Как запустить

### Что работает сразу, без установки
Презентация (.pptx), отчёты (results/), визуализации масок, метрики,
обученные примеры в rejected_examples/ — просто открываются двойным кликом.

### Проверка алгоритма вживую

Нужен Python 3.10+ (python.org, галочка "Add to PATH"). Дальше — два клика:

1. **`УСТАНОВКА.bat`** — сам найдёт Python, создаст окружение и поставит
   библиотеки (спросит: CPU ~300 МБ или GPU ~3 ГБ)
2. **`ЗАПУСК_ПРОГРАММЫ.bat`** — откроет графический интерфейс

Вручную то же самое:

    python -m venv .venv
    .venv\Scripts\activate
    pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128   :: GPU
    pip install -r requirements.txt                                                     :: CPU (~300 МБ)
    python predict.py --input demo_input --checkpoint model_trained/best_model.pth --save-masks

Замечание: при первом запуске .bat Windows может показать предупреждение
SmartScreen — это обычный фильтр для сценариев, нажимаете "Подробнее" →
"Выполнить в любом случае". На обычном компьютере без GPU обработка
одного полного кадра занимает ~12 секунд, мелких кадров — доли секунды.

### Переобучение с нуля (не обязательно, ~35 мин на GPU)

    python download_data.py 38cloud
    python dataset.py --prepare-38cloud
    python train.py --data-dir data/processed --epochs 16

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Двойной клик по .bat — окно мигнуло и исчезло | Не создан venv или не установлены библиотеки. Сценарий сам подскажет команду; выполните установку из раздела выше |
| Windows SmartScreen блокирует .bat | Фильтр для скачанных сценариев: «Подробнее» → «Выполнить в любом случае» |
| `python` открывает Microsoft Store | Python не установлен или не добавлен в PATH; ставьте с python.org и отметьте «Add to PATH» |
| Ошибка про segmentation-models-pytorch при загрузке модели | Библиотеки не установлены: `pip install -r requirements.txt` |
| Загрузка torch идёт 2–3 ГБ | Вариант с cu128 тянет CUDA-библиотеки; без NVIDIA GPU ставьте просто `pip install -r requirements.txt` (~300 МБ) |
| Обработка на CPU медленная | Нормально: полный кадр ~12 с, мелкие кадры — доли секунды |
| Кириллица в пути | Не проблема: чтение/запись файлов работает с русскими папками |

## Ограничения и что можно улучшить

Модель обучена на снимках Sentinel-2, а работает на снимках кубсатов —
датчики разные, поэтому часть погоды сеть может трактовать по-своему:
тонкая дымка иногда засчитывается как облака, а однородно-белые кадры,
наоборот, недооцениваются. Лечится дообучением на размеченных снимках
именно кубсатов: их можно разметить полуавтоматически (сеть предлагает
маску, человек правит). Дальше можно попробовать более тяжёлые архитектуры
(DeepLabV3+, SegFormer) и дополнительные каналы.
