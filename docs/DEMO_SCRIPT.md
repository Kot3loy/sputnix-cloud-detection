# Сценарий демонстрации на защите

Время: ~5–7 минут. Всё работает офлайн (данные уже скачаны).

## Подготовка (сделать заранее, до прихода жюри)

```bash
cd Sputnix
source .venv/Scripts/activate        # Windows Git Bash; или .venv\Scripts\activate

# 1. Убедиться, что модель обучена (файл существует):
#    outputs/checkpoints/best_model.pth
#    Если нет — python train.py --data-dir data/processed --epochs 16

# 2. Подготовить демо-папку (12 реальных снимков Спутникс + 6 синтетических,
#    включая 2 с облачностью >75%):
cp data/raw/sputnix/samples/*.jpg demo/demo_input/
cp data/synthetic/images/synth_00{29,30,31,39,41,48}.png demo/demo_input/

# 3. Разово прогнать, чтобы скриншоты легли в презентацию:
python predict.py --input demo/demo_input --save-masks
python build_pptx.py
```

## Что показать на экране (порядок)

### Шаг 1. Данные (30 сек)
Открыть папку `data/raw/sputnix/samples/` — реальные снимки с кубсатов
Спутникс (напомнить: ссылка из ТЗ). Показать 1–2 фото: «вот ясно,
а вот почти всё закрыто облаками».

### Шаг 2. Живой запуск обработки (2 мин)
В терминале:

```bash
python predict.py --input demo/demo_input --save-masks
```

Проговорить, пока бежит вывод:
* «Модель строит маску облаков для каждого снимка; перед этим кадр
  адаптивно нормализуется — убираем дымку некалиброванной камеры»;
* «Процент = облачные пиксели / валидные × 100»;
* «Всё, что больше 75% — уходит в rejected, остальное сохраняется».

Показать на выводе строки формата ТЗ (реальные числа финального прогона):
`Удалён: 2026-01-31_06-04-18_SXC3-232_1.jpg — облачность 77.4%.` (реальный кадр Спутникс)
`Удалён: synth_0031.png — облачность 94.3%.` (синтетика с GT 82%)
`Сохранён: 2025-11-03_..._SXC3-2334_1.jpg — облачность 2.2%.` (ясная река)

### Шаг 3. Результаты (1.5 мин)
Открыть в проводнике:
* `outputs/results/accepted/` — сохранённые снимки;
* `outputs/results/rejected/` — отбракованные (подчеркнуть: физически
  они не потеряны, мы используем безопасный режим; флаг --hard-delete
  удаляет по букве ТЗ);
* `outputs/results/report.csv` (Excel) и `report.json` — структурированные
  отчёты;
* `outputs/results/visualizations/<любой>_mask.jpg` — снимок с бирюзовой
  маской облаков и подписью процента — самое эффектное для жюри.

### Шаг 4. Метрики (1 мин)

```bash
python evaluate.py
```

Показать сводку: IoU, Dice, MAE процента облачности и матрицу ошибок
решения по порогу 75% (объяснить TP/FP/TN/FN своими словами).

### Шаг 5. Презентация (резерв)
`presentation/Sputnix_cloud_detection.pptx` — если жюри просит слайды.

## Возможные вопросы жюри и ответы

| Вопрос | Ответ |
|---|---|
| Почему нейросеть, а не «белое = облако»? | Эвристика путает облака со снегом, льдом, дымкой, пересветами; нейросеть учится текстуре и контексту. На наших снимках Спутникс есть явные примеры дымки, которую яркостный фильтр завалит. |
| Где брали разметку для обучения? | По ссылкам ТЗ снимки есть, но масок нет (проверено) — обучались на открытом 38-Cloud (Sentinel-2 с масками), а применяем к снимкам Спутникс. Это стандартный transfer learning. Дальнейшее развитие — дообучение на своей разметке. |
| Что если ровно 75%? | По ТЗ отбраковка «выше 75%», поэтому 75.0 сохраняется, отбраковка при строгом «больше». |
| А если модель ошибётся и удалит ценный снимок? | По умолчанию мы не удаляем, а перемещаем в rejected/ — ничего не теряется; --hard-delete включается осознанно. |
| Как считаете процент? | Пиксели маски / валидные пиксели × 100. Полностью чёрные (NODATA) пиксели из знаменателя исключены. |
| Сколько времени обрабатывается снимок? | Кадр 3280×2464 ≈ 0.5–1.5 с на GPU (тайлы 512 с перекрытием), на CPU — единицы секунд. |
| Можно ли улучшить? | Да: fine-tune на размеченных снимках Спутникс, более сильные бэкбоны (EfficientNet/SegFormer), учёт KML-телеметрии. |
