# Метрики качества решения

Решение задачи разбивается на три уровня, и на каждом — свои метрики.

## 1. Качество маски облаков (пиксельный уровень)

Модель выдаёт вероятность облака для каждого пикселя; пиксель считается
облачным при вероятности > 0.5. Сравниваем с ground-truth маской.

| Метрика | Формула | Что показывает |
|---|---|---|
| **IoU (Jaccard)** | TP / (TP + FP + FN) | доля общей площади предсказания и истины; главная метрика сегментации |
| **Dice (F1)** | 2·TP / (2·TP + FP + FN) | гармоническое среднее точности и полноты по пикселям |
| **Precision** | TP / (TP + FP) | доля верных среди названных облаками («не принимает снег за облако») |
| **Recall** | TP / (TP + FN) | доля найденных облаков («не пропускает облака») |

TP/FP/TN/FN считаются по пикселям: TP — предсказано облако и это правда,
FP — «облако» там, где чисто, и т.д.

*IoU усредняется по всем изображениям валидации; точное пиксельное IoU
накапливается по всему набору (сумма пересечений / сумма объединений).*

## 2. Точность процента облачности (уровень кадра)

Процент облачности кадра: `cloud% = облачные пиксели / валидные пиксели × 100`.
Для каждого снимка сравниваем предсказанный процент с истинным (по GT-маске):

* **MAE** (mean absolute error) — средняя абсолютная ошибка в процентных
  пунктах (п.п.). Например, MAE = 5 п.п. означает: в среднем процент
  угадывается с точностью ±5%.

## 3. Качество решения «отбраковать/сохранить» (бизнес-уровень, по ТЗ)

По ТЗ снимок отбраковывается при облачности **> 75%**. Строим матрицу
ошибок 2×2 по всем снимкам валидации:

| | Истина: брак (>75%) | Истина: сохранить (≤75%) |
|---|---|---|
| **Решение: отбраковать** | TP — верно отбракован | FP — зря отбракован (потеря данных!) |
| **Решение: сохранить** | FN — пропущен брак (плохие кадры дойдут до оператора) | TN — верно сохранён |

Считаются: **accuracy** (доля верных решений), **precision/recall/F1**
отбраковки. FP опаснее FN: зря удалённый снимок — потерянные данные
(поэтому по умолчанию включён безопасный режим перемещения в `rejected/`).

## 4. Как получить метрики

```bash
python evaluate.py --data-dir data/processed --checkpoint outputs/checkpoints/best_model.pth
```

Результат — `outputs/metrics/metrics.json`:

```json
{
  "mask_metrics": {"IoU": ..., "Dice": ..., "Precision": ..., "Recall": ...},
  "cloud_pct_MAE": ...,
  "threshold_75_confusion": {"tp_rejected_correctly": ..., "fp_rejected_wrongly": ...,
                             "tn_kept_correctly": ..., "fn_kept_wrongly": ...,
                             "decision_accuracy": ...},
  ...
}
```

Числа в презентации (`build_pptx.py`) подтягиваются из этого файла
автоматически; при его отсутствии ставятся явные плейсхолдеры.

## 5. Пороговые значения для школьного кейса (ориентир)

* IoU > 0.7 — уверенная сегментация облаков для кейса;
* MAE ≤ 7 п.п. — процент облачности пригоден для фильтра;
* decision accuracy > 90% при умеренном FP — решение готово к демо.
