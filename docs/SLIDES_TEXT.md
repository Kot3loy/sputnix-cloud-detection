## Слайд 2 — Проблема и цель

**Слева — проблема:**
— Спутники «Спутникс» делают тысячи снимков; значительная часть закрыта облаками и бесполезна для работы
— Просматривать вручную невозможно — нужен автоматический фильтр
— Требование заказчика: определять процент облачности и отсеивать снимки, закрытые более чем на 75%
— Оператор должен получать понятный отчёт: что сохранено, что удалено и почему

**Справа — цель проекта:**
— Модель сегментации: пиксель = облако или нет
— Расчёт процента облачности по маске
— Автоотбраковка по порогу 75% (по ТЗ — с удалением)
— Отчёт оператору: сохранённые и удалённые файлы с процентами

## Слайд 3 — Входные данные

* **Снимки «Спутникс» (ссылка из ТЗ).** Открытый ресурс disk.sputnix.ru:
  4 213 JPEG-снимка обзорных камер кубсатов SITRO-AIS, 3280×2464, RGB,
  ~200 м/пиксель, + KML-геопривязка. Использованы для инференса и демо.
* **38-Cloud — обучение.** Открытый датасет Sentinel-2: 8 400 патчей
  384×384 с масками облаков. В шеринга «Спутникс» масок нет, поэтому
  обучаем на 38-Cloud и применяем модель к снимкам «Спутникс» (transfer).
* **Почему нужна нейросеть?** Простая эвристика «яркое = облако» путает
  облака со снегом, льдом, дымкой и пересветами. Нейросеть учится
  текстуре и контексту.
* **Резерв: синтетика.** Свой генератор создаёт снимки с точными масками —
  smoke-тест пайплайна и запасное демо без интернета.

## Слайд 4 — Архитектура алгоритма

U-Net — стандарт для сегментации: сжимает изображение, извлекая признаки,
и восстанавливает маску в исходном разрешении.

**Схема:** Снимок 3×384×384 → Энкодер ResNet18 → Бутылочное горлышко →
Декодер → Маска облаков 1×384×384

— 13.7 млн параметров; выход — вероятность облака в каждом пикселе (сигмоида)
— Лосс: BCE + Dice; оптимизатор AdamW; смешанная точность (AMP)
— Fallback: собственная SmallUNet — работает даже без smp

## Слайд 5 — Пайплайн обработки снимка

**5 шагов:** 1. Загрузка → 2. Сегментация → 3. Подсчёт % → 4. Порог 75% → 5. Отчёт

— Формула процента: cloud_pixels / valid_pixels × 100
— Отбраковка по умолчанию безопасная — в rejected/; --hard-delete — удаление по ТЗ
— Кадр 3280×2464 обрабатывается ≈ 0.5–1.5 с на GPU

## Слайд 7 — Логика порога 75% и отбраковки

Требование ТЗ: если облака занимают больше 75% кадра — снимок не имеет
ценности и удаляется.

**Пример реального вывода:**
```
Сохранён: synth_0048.png — облачность 9.1%.
Удалён:   synth_0050.png — облачность 84.0%.
```

— >75% → перемещение в rejected/ (безопасно); ≤75% → в accepted/
— --hard-delete → буквальное удаление по ТЗ
— Отчёты: report.csv, report.json, operator_report.txt

## Слайд 10 — Ограничения и развитие

**Ограничения:**
— Domain gap: обучение на Sentinel-2, инференс на камерах кубсатов
— Тонкие перистые облака и дымка — самые сложные классы
— Снег/лёд могут распознаваться как облака
— Граница ровно 75% — зона шума метрики

**Развитие:**
— Дообучение на вручную размеченных снимках «Спутникс»
— Учёт KML-телеметрии (широтная климатология облачности)
— Более сильные модели: DeepLabV3+, SegFormer
— Полуавтоматическая доразметка: модель + проверка человеком
